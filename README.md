# 💍 Wedding Quiz

เกมตอบคำถามสดแบบ Kahoot สำหรับงานแต่งงาน — แขกเล่นบนมือถือ, คำถามและอันดับขึ้นจอโปรเจกเตอร์
รองรับผู้เล่น 150 คนขึ้นไป (ทดสอบแล้วจริง — ดูหัวข้อ [ทดสอบ](#-ทดสอบก่อนงานจริง))

A Kahoot-style live quiz for a wedding reception. Thai UI. Guests play on their phones,
the questions and leaderboard go on the projector.

---

## 3 หน้าที่ต้องรู้

| หน้า | ใคร | ทำอะไร |
|---|---|---|
| `/` | **แขก** (มือถือ) | ใส่ PIN → ตั้งชื่อ → ตอบคำถาม |
| `/host` | **เจ้าภาพ** (โน้ตบุ๊ก → โปรเจกเตอร์) | โชว์ PIN + QR, คุมเกม, โชว์อันดับ |
| `/admin` | **เจ้าภาพ** | แก้ไข/เพิ่ม/ลบคำถาม |

`/host` และ `/admin` ต้องใส่รหัสผ่าน = ค่า `HOST_PASSWORD` ที่ตั้งไว้

## 🚀 เอาขึ้นออนไลน์ (Render — ฟรี, ~10 นาที)

### 1. เอาโค้ดขึ้น GitHub

```bash
git init
git add .
git commit -m "Wedding quiz"
```

สร้าง repo เปล่าใน GitHub (ตั้งเป็น **Private** ก็ได้) แล้ว:

```bash
git remote add origin https://github.com/<ชื่อคุณ>/wedding-quiz.git
git push -u origin main
```

### 2. Deploy บน Render

1. สมัคร/ล็อกอินที่ [render.com](https://render.com) ด้วยบัญชี GitHub
2. กด **New** → **Blueprint** → เลือก repo นี้ (Render จะอ่าน `render.yaml` เอง)
3. Render จะถามค่า **`HOST_PASSWORD`** → ใส่รหัสที่คุณจะใช้เปิดจอเจ้าภาพ **(ตั้งให้เดายาก)**
4. กด **Apply** แล้วรอ ~3 นาที

เสร็จแล้วจะได้ URL หน้าตาแบบ `https://wedding-quiz-xxxx.onrender.com`

> ถ้าไม่อยากใช้ Blueprint: **New → Web Service** → เลือก repo →
> Build `npm install`, Start `npm start`, แล้วเพิ่ม Environment Variable `HOST_PASSWORD` เอง

### 3. ตั้งชื่อให้จำง่าย (แนะนำมาก)

ใน Render → Settings → **Name** เปลี่ยนเป็นอะไรสั้น ๆ เช่น `jun-wedding`
จะได้ URL เป็น `https://jun-wedding.onrender.com` — แขกพิมพ์ตามง่ายกว่าเยอะ

## 🔒 โหมดคำถามล็อก (pre-set) — เปิดไว้แล้วใน `render.yaml`

ตั้ง `LOCK_QUESTIONS=1` แล้วเซิร์ฟเวอร์จะอ่านคำถามจาก **`questions.seed.json` ที่อยู่ในโค้ดเท่านั้น**

- คำถามไม่มีทางหาย ต่อให้เซิร์ฟเวอร์รีสตาร์ท / redeploy / ย้ายโฮสต์
- ไม่ต้องใช้ดิสก์ถาวร → ใช้แผนฟรีได้สบาย
- `/admin` **ยังแก้ได้ตามปกติ** (เพิ่มข้อ ใส่รูป นำเข้าไฟล์ สำรองไฟล์) — แค่ปุ่ม
  **บันทึก** ที่เขียนลงเซิร์ฟเวอร์เท่านั้นที่ปิดอยู่ งานที่แก้จะถูกเก็บเป็น
  **ฉบับร่างในเบราว์เซอร์เครื่องนั้น** ให้อัตโนมัติ

นี่คือเหตุผลที่ทำแบบนี้: Render แผนฟรี **ไม่มีดิสก์ถาวร** อะไรที่เซฟลงเซิร์ฟเวอร์จะหาย
ตอนรีสตาร์ท เพราะฉะนั้น "ไฟล์" คือของจริง ไม่ใช่สิ่งที่เซิร์ฟเวอร์จำไว้

**วิธีแก้คำถาม (ทำที่ไหนก็ได้ ไม่ต้องใช้คอมตัวเอง):**
เข้า `https://<เว็บของคุณ>/admin` จากเครื่องไหนก็ได้ → แก้ให้พอใจ → กด
**"⬇ สำรองไฟล์"** → เอาไฟล์ที่ได้มาทับ `questions.seed.json` แล้ว push:

```bash
cp ~/Downloads/wedding-quiz-questions.json questions.seed.json
git add questions.seed.json && git commit -m "คำถามจริง" && git push
```

## ⚠️ เรื่องเดียวที่เหลือของ Render ฟรี: เว็บจะ "หลับ"

ถ้าไม่มีคนเข้า 15 นาที เซิร์ฟเวอร์จะหลับ ตื่นใหม่ใช้เวลา ~50 วินาที

**จัดการให้แล้ว:** หน้า `/host` จะยิง `/healthz` ทุก 4 นาทีอัตโนมัติ
→ ตราบใดที่จอเจ้าภาพเปิดอยู่ เซิร์ฟเวอร์จะไม่หลับเลย

**สิ่งเดียวที่ต้องทำ:** เปิดหน้า `/host` ทิ้งไว้ **10 นาทีก่อนเริ่มเกม**
(ครั้งแรกที่เปิดอาจรอ ~50 วินาที — หลังจากนั้นไม่ต้องรออีก)

> **ข้อจำกัดที่ทราบ:** ใครก็ตามที่รู้ `HOST_PASSWORD` จะคุมเกมได้ทั้งหมด (รวมถึงสวมรอยเป็นผู้เล่นคนอื่นได้)
> — ตั้งรหัสให้เดายาก อย่าโชว์บนจอ และอย่าใช้ค่า `changeme`

**ถ้าไม่อยากคิดเรื่องนี้เลย** มี 2 ทาง:

| ทางเลือก | ราคา | ข้อดี / ข้อเสีย |
|---|---|---|
| Render แผน **Starter** | ~$7/เดือน (ยกเลิกหลังงานได้) | ไม่หลับเลย, ไม่ต้องเปลี่ยนอะไรในโค้ด — ง่ายสุด |
| [Northflank](https://northflank.com/pricing) แผน **Sandbox** | ฟรี | โฆษณาว่า "always-on compute – no sleeping" และให้ 2 services ฟรี **แต่ต้องผูกบัตรเครดิตถึงจะสร้าง resource ได้** และตัวแพลตฟอร์มเองระบุว่าแผนฟรีไม่ได้มีไว้สำหรับงาน production |

> Koyeb แผนฟรีก็มี แต่ใช้ scale-to-zero (หลับเหมือน Render) จึงไม่ได้ช่วยอะไร

ไปที่ `https://<เว็บของคุณ>/admin` → ใส่รหัสผ่าน แล้ว:

- **ใส่รูปให้คำถามได้** (ดูหัวข้อถัดไป)
- กด **บันทึก**

## 🖼 ใส่รูปในคำถาม

ในแต่ละข้อจะมีแถวรูปอยู่ล่างสุด:

- **🖼 ใส่รูป** — เลือกไฟล์จากเครื่องหรือจากมือถือ รูปจะถูก **ย่อในเบราว์เซอร์ก่อนส่ง**
  (ด้านยาวเหลือ ~1000px, บันทึกเป็น JPEG) รูปจากมือถือ 4–5 MB มักเหลือราว ๆ 100 KB
- **🔗 ลิงก์รูป** — วางลิงก์รูปจากที่อื่นแทนก็ได้ ต้องขึ้นต้นด้วย `https://` เท่านั้น
  (ข้อเสีย: ถ้าเว็บต้นทางล่มหรือเน็ตงานช้า รูปจะไม่ขึ้น — แนะนำให้ใช้แบบเลือกไฟล์)
- **ลบรูป** — เอารูปออก

**รูปขึ้นเฉพาะบนจอใหญ่เท่านั้น ไม่ขึ้นบนมือถือแขก** — ตั้งใจให้เป็นแบบนี้ เหมือน Kahoot จริง
มือถือแขกจะเห็นแค่ปุ่มคำตอบสี่สี ทำให้แขก 150 คนไม่ต้องโหลดรูปพร้อมกัน (ซึ่งจะทำให้
เซิร์ฟเวอร์แผนฟรีเอาไม่อยู่)

> รูปหนึ่งใหญ่ได้ไม่เกิน ~300 KB หลังย่อ ถ้ารูปไหนใหญ่เกินระบบจะย่อซ้ำให้เอง
> ถ้ายังไม่ผ่านจะขึ้นข้อความบอกให้เปลี่ยนรูป

> แก้ได้เฉพาะตอนเกมยังไม่เริ่ม หรือจบเกมแล้ว — ถ้ากำลังเล่นอยู่ให้กด "รีเซ็ตเกม" ใน `/host` ก่อน
>
> **บนเซิร์ฟเวอร์จริงที่ตั้ง `LOCK_QUESTIONS=1` ปุ่ม "บันทึก" จะกดไม่ได้** —
> แก้ในหน้านี้ได้ตามปกติ แล้วกด "⬇ สำรองไฟล์" เอาไฟล์ไปทับ `questions.seed.json`
> แล้ว push แทน (ดูหัวข้อ "โหมดคำถามล็อก" ด้านบน)

## 🎤 วันงานจริง — ทำตามนี้

**ก่อนเริ่ม ~10 นาที**
1. เปิดโน้ตบุ๊กต่อโปรเจกเตอร์ → เข้า `https://<เว็บของคุณ>/host` → ใส่รหัสผ่าน
2. กด **F** เพื่อเข้าโหมดเต็มจอ
3. จอจะโชว์ **PIN ตัวใหญ่ + QR code** ให้แขกสแกน (สแกนแล้วใส่ PIN ให้อัตโนมัติ)

**ตอนเล่น**
| ปุ่ม | ทำอะไร |
|---|---|
| **▶ เริ่มเกม** / `Space` | เริ่มข้อแรก |
| **⏭ ข้ามเวลา** / `S` | ไม่รอหมดเวลา เฉลยเลย |
| **ถัดไป →** / `Space` | เฉลย → อันดับ → ข้อต่อไป |
| **🔒 ปิดรับผู้เล่น** | กันคนเข้าใหม่กลางเกม (ปิดอัตโนมัติตอนเริ่มเกม) |
| **👥 จัดการผู้เล่น** | เปิดรายชื่อผู้เล่น**ทั้งหมด** ค้นหาชื่อได้ และกด ✕ เพื่อเอาออก — ใช้ได้ทุกช่วงของเกม (ถ้ามีคนตั้งชื่อไม่เหมาะสม ใช้ปุ่มนี้) |
| **🔊 เสียง: เปิด / ปิด** | เปิด-ปิดเสียงเพลงและเสียงประกอบ — กดปิดได้ทันทีถ้า MC กำลังพูดหรือมีวงดนตรี (จำค่าไว้ให้) |
| **↺ กลับห้องรอ** | ล้างคะแนน กลับไปห้องรอ — **ผู้เล่นและ PIN เดิมยังอยู่ ไม่ต้องเข้าใหม่** |
| **🧹 ล้างทุกอย่าง** | ผู้เล่นหลุดหมด + PIN ใหม่ — ใช้ตอนอยากเริ่มจากศูนย์จริง ๆ |

> **ปุ่ม "เริ่มเกม" จะโผล่เฉพาะตอนอยู่ห้องรอ หรือจบเกมแล้ว** (ตอนจบเกมจะเปลี่ยนเป็น "▶ เล่นใหม่อีกรอบ")
> ถ้าติดอยู่กลางเกมแล้วอยากเริ่มใหม่ ให้กด **"↺ กลับห้องรอ"** ก่อน แล้วปุ่มเริ่มเกมจะกลับมา

- ถ้าทุกคนตอบครบก่อนหมดเวลา เกมจะเฉลยให้เองภายใน 1 วินาที
- ก่อนแต่ละข้อมีนับถอยหลัง 3-2-1 ให้แขกอ่านคำถามทัน
- แขกที่เน็ตหลุด กลับเข้ามาใหม่ได้เลย **คะแนนไม่หาย** (จำจากเครื่องแขกเอง)

**คะแนน:** ตอบถูก = 500–1000 คะแนน (ยิ่งเร็วยิ่งเยอะ) + โบนัสตอบถูกติดกัน +100 ต่อข้อ (สูงสุด +500)
ข้อที่ตั้ง "คะแนนคูณ 2" ได้ 1000–2000

## 🎵 เสียงเพลง

เสียงทั้งหมด **สังเคราะห์ขึ้นสด ๆ ในเบราว์เซอร์** (Web Audio API) — ไม่มีไฟล์ mp3 สักไฟล์เดียว
จึงไม่มีปัญหาลิขสิทธิ์ ไม่ต้องโหลดอะไรตอนงาน และไม่เพิ่มขนาด repo เลย

**เสียงออกที่จอใหญ่เท่านั้น ไม่ออกที่มือถือแขก** — ตั้งใจให้เป็นแบบนี้ เหมือน Kahoot จริง
ถ้ามือถือ 150 เครื่องเล่นเพลงพร้อมกันแต่ไม่ตรงจังหวะ จะกลายเป็นเสียงรบกวน

จังหวะเสียงตามช่วงเกม:

| ช่วง | เสียงที่ได้ยิน |
|---|---|
| ห้องรอ | **เพลงจังหวะสนุกวนลูปต่อเนื่อง** (กลอง + เบส + คอร์ด + เมโลดี้ 132 บีต/นาที) — คอร์ด C-G-Am-F 4 ห้อง วนได้ไม่จบ ไม่มีรอยต่อ |
| นับ 3-2-1 | บี๊ปไล่เสียงสูงขึ้นทีละขั้น |
| ระหว่างตอบ | เสียงติ๊กๆ + เสียงเต้นหัวใจ **ยิ่งเหลือเวลาน้อย ยิ่งถี่และสูงขึ้น** |
| หมดเวลา | เสียงออด |
| เฉลย | คอร์ดสดใส แล้วเงียบให้ MC พูด |
| กระดานคะแนน | เสียงไล่สูงขึ้นสั้น ๆ |
| โพเดียมจบเกม | แตรแฟนแฟร์ชัยชนะ |

> ตอนเปลี่ยนจากห้องรอไปคำถาม เพลงจะ **ค่อย ๆ เฟดออก** ไม่ตัดกลางคอร์ด

### ถ้าไม่ได้ยินเสียง

เบราว์เซอร์ห้ามไม่ให้เว็บเล่นเสียงเอง จนกว่าคนจะกดอะไรสักอย่างก่อน — ถ้าเข้าหน้า `/host` แล้ว
ระบบจำ session เข้าให้อัตโนมัติ (ไม่ได้กดอะไรเลย) เสียงจะโดนบล็อก

เวลานั้นปุ่มเสียงจะขึ้นว่า **"🔇 กดตรงนี้เพื่อเปิดเสียง"** และกะพริบสีทอง — **กดตรงไหนก็ได้บนหน้านั้น** เสียงจะมาทันที

> อย่าลืม**ต่อลำโพงจากโน้ตบุ๊กเข้าเครื่องเสียงของงาน** และเช็คว่าไม่ได้ปิด mute ไว้

| `LOCK_QUESTIONS` | ปิด | `1` = อ่านคำถามจาก `questions.seed.json` เท่านั้น, `/admin` อ่านอย่างเดียว |
| `MAX_PLAYERS` | `300` | จำนวนผู้เล่นสูงสุด |
| `DATA_DIR` | `./data` | ที่เก็บ `questions.json` และ state สำรอง |
